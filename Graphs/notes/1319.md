
# LC 1319 — Number of Operations to Make Network Connected

## Pattern
Graph DFS — Connected Components + Minimum Connections

## 1. Problem Understanding

We have `n` computers connected by network cables.

A connection joins two computers. We can remove an existing cable and use it to connect two computers that are not connected.

We need to find the minimum number of operations required to connect every computer.

If it is impossible, return `-1`.

## 2. Approach

1. Check whether the number of connections is at least `n - 1`.
2. If not, return `-1`. There are not enough cables to connect all computers.
3. Build an adjacency list from the connections.
4. Create a `visited` array.
5. Traverse every computer using the outer loop.
6. Whenever we find an unvisited computer:
    - Increment `countOfComponents`.
    - Run DFS to visit every computer in that connected component.
7. Return `countOfComponents - 1`.

## 3. Why Check connections.length < n - 1?

```java
if(connections.length < n-1){
    return -1;
}
```

To connect `n` computers into one connected network, at least `n - 1` cables are required.

For example, connecting four computers in a chain requires three cables:

0 — 1 — 2 — 3

If we have fewer than `n - 1` cables, connecting every computer is impossible.

This is a necessary condition, so we check it before building the graph.

## 4. Building the Adjacency List

```java
for(int[] edge : connections){
    int u = edge[0];
    int v = edge[1];

    graph.get(u).add(v);
    graph.get(v).add(u);
}
```

The network is undirected, so every connection must be stored in both directions.

If a cable connects computer 0 to computer 1:
- Computer 0's list contains 1.
- Computer 1's list contains 0.

## 5. Counting Connected Components

```java
for(int i=0;i<n;i++){
    if(!visited[i]){
        countOfComponents++;
        dfs(i,graph,visited);
    }
}
```

Each DFS traversal visits one complete connected component.

The outer loop ensures that disconnected components are also discovered.

Example:

0 — 1     2 — 3     4

There are three connected components:
- Component 1: computers 0 and 1
- Component 2: computers 2 and 3
- Component 3: computer 4

Therefore, `countOfComponents = 3`.

## 6. Why Is the Answer Components - 1?

If there are `k` disconnected components, we need `k - 1` operations to connect them all.

For example, three components need two connections:

Component A + Component B + Component C

- One operation joins A and B.
- Another operation joins the combined group to C.

The initial cable-count check guarantees that enough cables exist to make these connections.

Therefore:

```java
return countOfComponents - 1;
```

## 7. Example

Input:

```text
n = 4
connections = [[0,1], [0,2], [1,2]]
```

There are three cables, and `n - 1 = 3`, so the initial check passes.

The graph has two components:
- Component 1: computers 0, 1 and 2
- Component 2: computer 3

One operation is required.

Output:

```text
1
```

## 8. Edge Cases

### Case 1: Not enough cables

```text
n = 4
connections = [[0,1], [2,3]]
```

There are only two cables, but three are required at minimum.

Output: `-1`

### Case 2: Already connected

```text
n = 3
connections = [[0,1], [1,2]]
```

There is one connected component.

Output: `0`

### Case 3: Every computer is isolated

For `n = 4`, if there are at least three connections but they all form redundant cycles within a subset of computers, some computers can remain isolated.

The answer is `components - 1`, provided the initial cable-count condition passes.

### Case 4: One computer

```text
n = 1
connections = []
```

Output: `0`

One computer is already connected to itself; no operation is required.

## 9. Common Mistakes

1. Forgetting the `n - 1` cable requirement.
2. Adding an undirected connection in only one direction.
3. Incrementing the component count for every computer rather than only unvisited computers.
4. Forgetting to mark a computer visited in DFS.
5. Returning the number of components instead of `components - 1`.
6. Assuming that enough cables automatically means the network is connected. We must still count the components.

## 10. Complexity Analysis

Let `n` be the number of computers and `m` be the number of connections.

### Time Complexity: O(n + m)

- Building the adjacency list: O(n + m), including initialization.
- DFS traversal: O(n + m).
- Counting components: O(n).

Overall: O(n + m).

### Auxiliary Space Complexity: O(n + m)

- Adjacency list: O(n + m).
- Visited array: O(n).
- DFS recursion stack: O(n) in the worst case.

Overall: O(n + m) auxiliary space.

## 11. Interview Takeaway

Ask yourself:

1. What are the nodes? Computers.
2. What are the edges? Network cables.
3. Why check `n - 1`? A connected network needs at least that many cables.
4. How do we count disconnected groups? DFS and a visited array.
5. Why `components - 1`? Connecting k components requires k - 1 operations.

**Recognition pattern:** When a graph needs to be connected using existing or reusable edges, first check whether enough edges exist, then count connected components.
