
# LC 785 — Is Graph Bipartite?

## Pattern
Graph Coloring + DFS + Disconnected Components

## Core Idea

A graph is bipartite if we can divide its nodes into two groups such that
no two adjacent nodes belong to the same group.

We represent the two groups using colors:
- Color 0
- Color 1

Every edge must connect nodes of different colors.

## Approach

1. Create a `color` array with one entry per node.
2. Fill the array with `-1`, meaning uncolored.
3. Loop through every node.
4. If a node is uncolored, start DFS with color `0`.
5. During DFS:
    - Color the current node.
    - If a neighbor is uncolored, give it the opposite color.
    - If a neighbor already has the same color as the current node, return `false`.
6. If every component is colored without conflicts, return `true`.

## Important Conditions

### 1. Uncolored neighbor

`color[neighbor] == -1`

The neighbor has not been visited through coloring yet.
Recursively visit it with the opposite color.

### 2. Coloring rule

`1 - currentColor`

- If the current color is `0`, the next color is `1`.
- If the current color is `1`, the next color is `0`.

### 3. Conflict detection

`color[neighbor] == currentColor`

Both endpoints of an edge have the same color.
The graph cannot be bipartite, so return `false`.

## Why Check Every Node?

The graph may be disconnected.

Starting DFS only from node `0` could leave other components unchecked.

The outer loop starts DFS from every uncolored node, ensuring every component is checked.

## Edge Cases

- Empty graph: returns `true`.
- Single isolated node: returns `true`.
- Multiple disconnected components: every component must be checked.
- Self-loop: returns `false`, because a node is adjacent to itself.
- Odd-length cycle: returns `false`.
- Even-length cycle: returns `true`.
- Graph with no edges: returns `true`.

## Common Mistakes

1. Initializing every color to `0` instead of `-1`.
    - This makes it impossible to distinguish uncolored nodes.

2. Forgetting to use the opposite color for a new neighbor.

3. Checking only whether a neighbor is visited.
    - The important check is whether an already-colored neighbor has the same color.

4. Starting DFS only from node `0`.
    - This misses disconnected components.

5. Forgetting to propagate `false` from recursive DFS calls.

## Complexity

Let:
- V = number of vertices
- E = number of edges

Time: O(V + E)

Each vertex is colored once, and each adjacency-list entry is examined.

Auxiliary space: O(V)

The color array and recursive DFS stack can each use O(V) space.

## Interview Takeaways

- Bipartite checking can be solved using DFS or BFS.
- Two-coloring is the central idea.
- A graph is bipartite if and only if it contains no odd-length cycle.
- Always handle disconnected components.
- In this problem, the adjacency list is already provided as `int[][] graph`.
