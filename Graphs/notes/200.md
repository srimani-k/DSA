
# LC 200 — Number of Islands

## Pattern
Grid DFS + Connected Components

## Core Idea

- `'1'` represents land.
- `'0'` represents water.
- An island is a group of connected land cells.
- Only up, down, left, and right connections count.

We need to count how many separate land regions exist.

## Approach

1. Traverse every cell using nested loops.
2. If the current cell is water (`'0'`), skip it.
3. If the current cell is land (`'1'`):
    - Increment `countIslands`.
    - Start DFS to explore the entire connected island.
4. In DFS:
    - Stop if the coordinates are outside the grid.
    - Stop if the current cell is water.
    - Change land to water to mark it as visited.
    - Explore all four directions.
5. Return `countIslands`.

## Why Increment Before DFS?

The first unvisited land cell found by the outer loops represents a new island.

We increment the count once, then DFS visits all land connected to that cell.

Those cells are changed to `'0'`, so the outer loops won't count them again.

## Why Modify '1' to '0'?

This marks the land as visited without requiring a separate `visited` array.

It also prevents DFS from repeatedly exploring the same cells.

## Edge Cases

- Empty grid: the usual constraints guarantee a non-empty grid; otherwise, add an empty-grid guard.
- All water: answer is `0`.
- All land: answer is `1`.
- One land cell surrounded by water: answer is `1`.
- Multiple separate land regions: each region contributes `1`.
- Land connected only diagonally: those cells belong to separate islands.

## Common Mistakes

1. Counting every land cell instead of every connected region.
2. Forgetting to mark land as visited before exploring neighbors.
3. Forgetting boundary checks.
4. Using `"1"` instead of `'1'` for a Java `char`.
5. Exploring diagonals when only four-directional connectivity is allowed.

## Complexity

Let:
- m = number of rows
- n = number of columns

Time: O(m × n)

Every cell is processed at most a constant number of times.

Auxiliary space: O(m × n) worst case.

The recursive DFS stack can grow to the size of the grid in the worst case.

The grid is modified in place, so no separate visited array is needed.

## Interview Takeaways

- The outer loops discover new connected components.
- DFS consumes or marks the entire component.
- Count when discovering a new component, not during every DFS visit.
- This is the same connected-component idea used in graph problems, adapted to a grid.
