
# LC 130 — Surrounded Regions

## Pattern
Boundary DFS + Grid Traversal + In-Place Marking

## Core Idea

- `X` represents a blocked cell.
- `O` represents an open cell.
- An `O` region should be changed to `X` if it is completely surrounded.
- An `O` connected to the boundary must remain `O`.

Instead of searching for every surrounded region directly, find the `O` cells that cannot be captured.

## Approach

### Step 1: Handle an empty board

If the board has no rows or no columns, return immediately.

### Step 2: Explore all four boundaries

Start DFS from every boundary cell containing `O`:

- Left boundary: `col == 0`
- Right boundary: `col == n - 1`
- Top boundary: `row == 0`
- Bottom boundary: `row == m - 1`

DFS explores all `O` cells connected to each starting boundary cell.

### Step 3: Temporarily mark safe cells

Inside DFS:
1. Stop if the coordinates are outside the board.
2. Stop if the cell is `X`.
3. Stop if the cell is already `#`.
4. Change `O` to `#`.
5. Explore all four directions.

The `#` marker means that this cell is connected to the boundary and must survive.

### Step 4: Restore and capture

Traverse the entire board:

- Change remaining `O` cells to `X`.
- Change temporary `#` markers back to `O`.

Now only surrounded regions have been captured.

## Why Start From the Boundary?

A region connected to the boundary cannot be completely surrounded by `X`.

Starting from boundary `O` cells lets us identify every cell that must remain unchanged.

## Example

Before:

X X X X
X O O X
X X O X
X O X X

The `O` region in the middle is surrounded and becomes `X`.

The `O` at the bottom boundary remains `O`.

After:

X X X X
X X X X
X X X X
X O X X

## Edge Cases

- Empty board: return immediately.
- One row or one column: all cells are on the boundary, so no `O` should be captured.
- All `X`: board remains unchanged.
- All `O`: every cell is boundary-connected, so all remain `O`.
- An `O` region touching any boundary: preserve the entire connected region.
- An isolated interior `O`: capture it.

## Common Mistakes

1. Starting DFS from every `O` and immediately changing it to `X`.
    - This can capture boundary-connected cells incorrectly.

2. Exploring only one or two boundaries.
    - All four boundaries must be checked.

3. Forgetting to restore `#` to `O`.

4. Forgetting to convert remaining `O` to `X`.

5. Not marking cells before exploring neighbors.
    - This can cause repeated traversal.

6. Using a temporary marker that could be confused with a valid board value.
    - `#` is safe here because the input contains only `X` and `O`.

## Complexity

Let:
- m = number of rows
- n = number of columns

Time: O(m × n)

Each cell is processed at most a constant number of times.

Auxiliary space: O(m × n) worst case.

The recursive DFS stack can grow to O(m × n) in the worst case.

The board itself is modified in place, so no separate visited array is needed.

## Interview Takeaways

- Think about which cells are safe before deciding which cells to change.
- Boundary traversal is useful when boundary-connected cells must be preserved.
- In-place marking can replace a separate visited array.
- The pattern is: identify safe cells -> mark them -> capture the rest -> restore safe cells.
